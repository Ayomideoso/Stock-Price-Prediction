Tesla Next-Day Stock Price Forecasting with XGBoost¶

Project objective¶

This project uses historical Tesla (TSLA) market data to build a one-day-ahead forecasting model.

Rather than having XGBoost predict the raw future stock price, the revised model forecasts the next-day percentage return and converts it to a predicted closing price. This approach is better suited for tree-based models when stock prices enter ranges not seen during training.

The model is evaluated against a straightforward benchmark: tomorrow's closing price equals today's closing price.

Engineer time-series features¶

I created features using only information available by the end of each trading day. These include daily returns, trading range, price movement, volume change, lagged returns and rolling trend/volatility measures.

The target is the next days return, which is later converted back into a predicted closing price.

In [5]:
model_df = df.copy()

# Current-day information available before predicting the following trading day.
model_df["return_1d"] = model_df["close"].pct_change()
model_df["log_return_1d"] = np.log(model_df["close"] / model_df["close"].shift(1))
model_df["range_pct"] = (model_df["high"] - model_df["low"]) / model_df["close"]
model_df["open_close_pct"] = (model_df["close"] - model_df["open"]) / model_df["open"]
model_df["volume_change"] = model_df["volume"].pct_change()
model_df["volume_change"] = model_df["volume_change"].replace([np.inf, -np.inf], np.nan)

# Lagged return and price-momentum features.
for lag in [1, 2, 3, 5, 10, 15]:
    model_df[f"return_lag_{lag}"] = model_df["return_1d"].shift(lag - 1)
    model_df[f"close_ratio_lag_{lag}"] = model_df["close"] / model_df["close"].shift(lag) - 1

# Rolling trend, volatility and volume features.
for window in [3, 5, 10, 15, 20]:
    model_df[f"return_mean_{window}"] = model_df["return_1d"].rolling(window).mean()
    model_df[f"return_std_{window}"] = model_df["return_1d"].rolling(window).std()
    model_df[f"volume_ratio_{window}"] = model_df["volume"] / model_df["volume"].rolling(window).mean()
    model_df[f"close_ma_ratio_{window}"] = model_df["close"] / model_df["close"].rolling(window).mean() - 1

# One-day-ahead targets.
model_df["target_return"] = model_df["close"].shift(-1) / model_df["close"] - 1
model_df["target_close"] = model_df["close"].shift(-1)

feature_cols = [
    c for c in model_df.columns
    if (
        c in ["return_1d", "log_return_1d", "range_pct", "open_close_pct", "volume_change"]
        or c.startswith("return_lag_")
        or c.startswith("close_ratio_lag_")
        or c.startswith("return_mean_")
        or c.startswith("return_std_")
        or c.startswith("volume_ratio_")
        or c.startswith("close_ma_ratio_")
    )
]

model_df = model_df.dropna(
    subset=feature_cols + ["target_return", "target_close"]
).reset_index(drop=True)

print("Modelling rows:", len(model_df))
print("Number of features:", len(feature_cols))

Tune XGBoost using time-series cross-validation¶

I used TimeSeriesSplit to make sure each validation fold comes after its training fold. I chose hyperparameters based on the mean absolute error for next-day returns, making sure that future data did not leak into earlier training periods.

In [8]:
param_grid = {
    "n_estimators": [50, 100, 200],
    "max_depth": [1, 2],
    "learning_rate": [0.01, 0.03, 0.05],
    "subsample": [0.8],
    "colsample_bytree": [0.8]
}

tscv = TimeSeriesSplit(n_splits=5)

grid_search = GridSearchCV(
    estimator=XGBRegressor(
        objective="reg:squarederror",
        random_state=RANDOM_STATE,
        n_jobs=1
    ),
    param_grid=param_grid,
    scoring="neg_mean_absolute_error",
    cv=tscv,
    n_jobs=1
)

grid_search.fit(X_train, y_train)

best_model = grid_search.best_estimator_

print("Best parameters:", grid_search.best_params_)
print(f"Best CV return MAE: {-grid_search.best_score_:.5f}")

Conclusion¶

This revised workflow fixes the main methodological weaknesses in the original notebook:

  • it preserves chronological order;
  • it avoids fitting a scaler to future test data;
  • it predicts returns rather than asking a tree model to extrapolate unseen raw price levels;
  • it reports MAE and RMSE in actual dollars;
  • it uses a meaningful previous-close benchmark;

Result interpretation¶

During this holdout period, XGBoost and the previous-close baseline perform similarly. XGBoost has a slightly lower MAE, while the naive benchmark has a slightly lower RMSE. The XGBoost model reaches about 53.5% directional accuracy.

So, the right conclusion is that XGBoost does not have a real forecasting advantage over the simple baseline for this dataset and test period. This is an important finding. Financial time series are hard to predict, and a complex model should not be considered successful simply because its error appears small.
